Çok güzel soru! Bu Spring'in dependency injection mantığının özüdür. İşte nasıl çalıştığı:
Spring'in Dependency Injection Sihri:
1. Spring Context Başlatma Süreci:
text

AppConfig.employeeList() → EmployeeRepository → EmployeeService → EmployeeController

2. Adım Adım Açıklama:

1. AppConfig'de Bean Tanımı:
java

@Bean
public List<Employee> employeeList() {
    // Bu metod Spring başlarken ÇALIŞTIRILIR
    List<Employee> employees = new ArrayList<>();
    employees.add(new Employee("1", "John", "Doe"));
    // ...
    return employees; // Bu liste Spring Context'e kaydedilir
}

2. EmployeeRepository Oluşturulması:
java

@Repository
public class EmployeeRepository {
    private List<Employee> employees;

    // Spring bu constructor'ı çağırırken
    // Context'teki "List<Employee>" bean'ini otomatik enjekte eder
    public EmployeeRepository(List<Employee> employees) {
        this.employees = employees; // employees ARTIK DOLU!
    }
}

3. EmployeeService:
java

@Service
public class EmployeeService {
    private final EmployeeRepository employeeRepository;
    
    // Spring burada EmployeeRepository'yi enjekte eder
    public EmployeeService(EmployeeRepository employeeRepository) {
        this.employeeRepository = employeeRepository;
    }
}

Detaylı Akış:
text

Spring Uygulaması Başlar
        ↓
AppConfig sınıfı taranır
        ↓
@Bean public List<Employee> employeeList() ÇALIŞTIRILIR
        ↓
Oluşturulan liste Spring Context'e kaydedilir
        ↓
EmployeeRepository sınıfı taranır
        ↓
Spring: "Bu sınıfın List<Employee> tipinde bağımlılığı var"
        ↓
Spring: "Context'te List<Employee> tipinde bir bean var"
        ↓
Spring employeeList bean'ini EmployeeRepository constructor'ına ENJEKTE EDER
        ↓
EmployeeRepository.employees artık dolu liste içeriyor!

Görselleştirme:
java

// 1. Spring bu bean'i oluşturur ve saklar
List<Employee> employeeListBean = Arrays.asList(
    new Employee("1", "John", "Doe"),
    new Employee("2", "Jane", "Smith")
);

// 2. Spring EmployeeRepository oluştururken:
EmployeeRepository repo = new EmployeeRepository(employeeListBean);
//                                 ↑
//                         Burada enjekte ediyor!

Kontrol Etmek İçin:

Repository'nize bir log ekleyerek görebilirsiniz:
java

@Repository
public class EmployeeRepository {
    private List<Employee> employees;

    public EmployeeRepository(List<Employee> employees) {
        this.employees = employees;
        System.out.println("EmployeeRepository oluşturuldu! Employee sayısı: " + employees.size());
        // Çıktı: "EmployeeRepository oluşturuldu! Employee sayısı: 3"
    }
}

Özetle: Spring, @Bean ile oluşturduğunuz listeyi context'te saklar ve bu tipte bağımlılığı olan tüm sınıflara otomatik olarak enjekte eder. Bu nedenle EmployeeRepository constructor'ına gelen liste dolu gelir!
// Context'teki "List<Employee>" bean'ini otomatik enjekte eder derken bean bu Repository gördüğü nada direk enjekte mi eder

Hayır, tam olarak öyle değil. Spring'in akıllı bir eşleştirme mekanizması var. Detaylı açıklıyorum:
Spring'in Bean Eşleştirme Mantığı:
1. "Type-Based" Injection (Tipe Göre Enjeksiyon)

Spring şu sırayla düşünür:
java

// 1. Spring Context'teki BEAN'leri arar:
//    "Acaba List<Employee> tipinde bir bean var mı?"

// 2. AppConfig'de bulur:
@Bean
public List<Employee> employeeList() { // ← EVET! Bu bean uyuyor
    return Arrays.asList(...);
}

// 3. EmployeeRepository constructor'ına bu bean'i enjekte eder

2. Eğer Aynı Tipte Birden Fazla Bean Olsaydı:
java

@Configuration
public class AppConfig {
    
    @Bean
    public List<Employee> employeeList() {
        // normal employees
    }
    
    @Bean 
    public List<Employee> managerList() {
        // sadece manager'lar
    }
}

Bu durumda hata alırsınız çünkü Spring hangisini enjekte edeceğini bilemez.
3. Çözüm: @Qualifier Kullanımı
java

@Configuration
public class AppConfig {
    
    @Bean
    @Qualifier("regularEmployees") // ← Bean'e isim veriyoruz
    public List<Employee> employeeList() {
        // ...
    }
    
    @Bean
    @Qualifier("managers") // ← Bean'e isim veriyoruz  
    public List<Employee> managerList() {
        // ...
    }
}

@Repository
public class EmployeeRepository {
    // Hangi bean'i istediğimizi belirtiyoruz
    public EmployeeRepository(@Qualifier("regularEmployees") List<Employee> employees) {
        this.employees = employees;
    }
}

Spring'in Düşünce Süreci:
text

Spring Application Context başlıyor...
    ↓
Tüm @Bean, @Component, @Service, @Repository'leri tarıyor
    ↓
EmployeeRepository bulundu → Constructor'ında List<Employee> parametresi var!
    ↓
Spring: "Context'te List<Employee> tipinde bean var mı?"
    ↓
AppConfig.employeeList() → EVET! List<Employee> döndürüyor
    ↓
Spring bu bean'i EmployeeRepository constructor'ına ENJEKTE EDER
    ↓
EmployeeRepository artık hazır!

Basit Analoji:
java

// Manuel olarak yapsaydık:
List<Employee> employeeList = appConfig.employeeList(); // Bean'i al
EmployeeRepository repo = new EmployeeRepository(employeeList); // Enjekte et

// Spring bunu otomatik yapıyor:
EmployeeRepository repo = new EmployeeRepository(/* Spring burayı otomatik doldurur */);

Önemli Nokta:

Spring reflection kullanarak constructor parametrelerinin tipini analiz eder ve context'te bu tipte bir bean varsa otomatik enjekte eder.

Yani: Spring EmployeeRepository'yi gördüğünde, constructor'ındaki parametre tipine bakar, context'te o tipte bir bean arar, bulursa enjekte eder!
